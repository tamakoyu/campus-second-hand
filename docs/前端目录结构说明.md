# 前端目录结构说明（V0.1 工程骨架）

> 对应《前端开发计划书》步骤 2；与组长确认后按此搭建。
> 所有目录职责与命名规范见文末"目录约定"。

## 2. 目录约定

| 目录 | 职责 | 禁止事项 |
| --- | --- | --- |
| `src/api` | 接口封装唯一出口；函数按域命名 `goodsApi.getList()` | 页面组件直接调 axios |
| `src/components/common` | 通用组件：无业务依赖、props 驱动、可被任意页面复用 | 组件内请求接口 |
| `src/components/business` | 业务组件：可依赖 api/store，但必须可独立测试 | 与页面强耦合的私有代码 |
| `src/layouts` | 页面框架与导航结构 | 承载具体业务逻辑 |
| `src/router` | 路由表 + 懒加载 + 守卫 | 页面内硬编码跳转逻辑 |
| `src/store` | Pinia 按域拆分，跨页共享状态 | 单页私有状态（用 ref 即可） |
| `src/styles` | 全局 token 与覆盖；组件样式一律 scoped | 页面写死颜色/间距魔法值 |
| `src/composables` | 组合式函数（useXxx）：页面数据编排、可复用业务逻辑 | 放 UI 组件 |
| `src/utils` | 纯函数工具 | 放 UI 组件 |
| `src/views` | 页面目录，只做组合编排（页面私有子组件放 views/<Page>/components/） | 塞入大量业务逻辑 |

## 3. 工程约定

- 路径别名：`@` → `src`（vite.config.js 配置），import 一律用 `@/...`。
- 环境变量：`VITE_API_BASE_URL` 区分 dev/prod；开发代理 `/api` → `http://localhost:8080`（后端地址，v1.1 确认），避免跨域。
- 路由（已与团队确认，2026-09）：全部懒加载，路由表如下：

| 路由 | 页面 | 负责人 |
| --- | --- | --- |
| `/` | 首页 | 范胜洲 |
| `/products` | 商品列表 / 检索 | 范胜洲 |
| `/product/:id` | 商品详情 + AI 问答 | 范胜洲 |
| `/login` | 登录 | 徐家凯 |
| `/register` | 注册 | 徐家凯 |
| `/center` | 个人中心（profile / publish / favorites / orders） | 徐家凯 |
| `/publish` | AI 发布 | 徐家凯 |
| `/message` | 私信 | 徐家凯 |
| `/admin` | 管理后台（dashboard / audit / users / disputes） | 徐家凯 |
| `/404` | 404 | 公共 |

- 后端联调约定已确认（详见《docs/前端联调约定.md》）：统一前缀 `/api`；响应 `{code, message, data}`；分页 `{list, total, page, pageSize}`（`?page=&pageSize=`，page 从 1 起、默认 10、最大 100）；金额单位「分」前端展示时 /100；时间 `yyyy-MM-dd HH:mm:ss`；认证 JWT Bearer（联调期暂用请求头 `X-User-Id: 1`）；普通接口 axios 超时 10s、AI 接口 20s；图片 base64 ≤5MB（建议压缩至 ≤1MB）。
- Element Plus：按需引入（unplugin-vue-components 自动按需），主题色通过 `element-override.scss` 覆盖为设计 token。
- mock：联调前在 `mock/` 提供按接口文档结构的假数据，接口就绪后无缝切换（仅改 request.js baseURL/开关）。
