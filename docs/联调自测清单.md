# 联调自测清单（范胜洲前端 · 步骤 9）

> 依据：后端实际代码（main 分支 `backend/`，田博 2026-09-01）+《接口约定规范 v1.1》+《前端联调约定》
> 目的：前后端契约对齐核对结果 + 按接口逐一自测的 curl 与预期，方便联调时直接照做。
> 当前后端状态：`ai.enabled=false, ai.mock=true`（规则引擎/Mock 响应，零网络依赖）；无 /api/auth，`UserContext` 默认 userId=1。

## 0. 启动与准备

- 后端：`backend/` 是 Maven 工程，PostgreSQL 库 `second_hand`（schema 见 `backend/sql/schema.sql`）；启动后端口 8080。
- 前端：`npm run dev`（5173），vite 代理 `/api -> localhost:8080`；CORS 已放行 5173/3000。
- 金额：接口层全部为整数「分」（后端 `MoneyUtil` 确认），前端展示除以 100。
- 联调账号：后端暂无 /api/auth，登录接口未实现；所有接口按 userId=1 生效（Bearer 解析为 Noop）。

## 1. 商品列表 / 检索（GET /api/products）

```bash
curl 'http://localhost:8080/api/products?keyword=键盘&category=digital&condition=90&minPrice=1000&maxPrice=20000&sort=hot&page=1&size=12'
```

预期：`{code:0, data:{list:[...], total, page, pageSize}}`；list 元素字段见 ProductListItemVO（id/title/price/originalPrice/cover/category/categoryName/condition/conditionName/views/createdAt/seller）。

**核对结论（前端已适配）**：
- 分页参数后端为 **`size`**（v1.1 §7.1 写的是 pageSize，响应仍是 pageSize）→ 前端已改发 `size`；**待组长更新规范**。
- keyword 匹配标题+描述；category 用字符串 key（book/digital/...）；condition 用 100/90/80/70；sort=latest/price_asc/price_desc/hot —— 与前端一致 ✅
- minPrice/maxPrice 单位分 ✅

## 2. 商品详情（GET /api/products/{id}）

```bash
curl 'http://localhost:8080/api/products/1'
```

预期：ProductVO（含 description/estimatedPrice/cover/.../seller/favorited/favoriteCount/images）；views 自增 1；不存在 → 40401。

**核对结论**：前端详情页字段全部匹配；**estimatedPrice（AI 建议价，分）已上屏展示**；favorited 已用于收藏按钮状态。

## 3. 收藏 toggle（POST /api/favorites/{productId}）

```bash
curl -X POST 'http://localhost:8080/api/favorites/1'
curl -X POST 'http://localhost:8080/api/favorites/1'   # 再点一次取消
```

预期：`{code:0, data:{favorited:true}}` → 再调返回 false。

**核对结论**：前端详情页收藏按钮已接入（黑星实心=已收藏，成功提示不用绿色）。

## 4. 猜你喜欢（GET /api/products/recommend）

```bash
curl 'http://localhost:8080/api/products/recommend?limit=8'
```

预期：`{code:0, data:[ProductListItemVO...]}`（**裸数组**，无 items 包裹、无 reason 字段）。

**核对结论（前端已适配）**：
- v1.1 §8 的 `GET /api/ai/recommend?scene=&productId=` **后端未实现**，实际为上述路径；前端已改调 `/products/recommend`，reason 由前端补兜底文案（首页"猜你喜欢"、详情"为你推荐"）。
- **待组长/后端补充**：scene=detail 同分类推荐、推荐理由字段。
- 失败降级：接口挂了前端自动降级为最新商品（步骤 7 已实现）。

## 5. AI 估价（POST /api/ai/estimate，登录态 userId=1）

```bash
curl -X POST 'http://localhost:8080/api/ai/estimate' -H 'Content-Type: application/json' -d '{"originalPrice":19900,"category":"digital","condition":90}'
```

预期：`{code:0, data:{suggestPrice(分), priceRange:{min,max}(分), reason, engine("llm"|"rule"), source}}`；AI 不可用自动降级规则引擎（engine=rule）。

**核对结论**：前端 `ai.js estimate` 入参/出参匹配（金额分）✅；详情页建议价当前直接展示详情接口返回的 estimatedPrice，如需实时估价按钮可在此接口就绪后补。

## 6. 枚举字典（GET /api/dicts）

```bash
curl 'http://localhost:8080/api/dicts'
```

预期：`{categories:[{id,parentId,name}], conditions:[{value:100,name:全新}...], productStatus, orderStatus}`。

**核对结论**：conditions/productStatus/orderStatus 与前端 `utils/dict.js` 一致；categories 为数据库 id/name（发布表单用，属徐家凯范围）；前端展示仍用后端返回的 categoryName，无需改动。
